# Project Plan — Tat Tvam Asi

## 1. 基本信息

* **名称**：Tat Tvam Asi（彼即汝）
* **性质**：Rust 与中观概念的对照实验
* **目标**：用可编译的约束，练习「无自性 / 缘起 / 不落两边」在工程中的可操作含义

本项目不建立个人哲学中心，不宣称掌握「逻辑圣言」或「宇宙本质」。

---

## 2. 三个对照（均为近似，非等同）

### 对照一：生灭与所有权

* 中观侧：诸法因缘生，因缘灭；无独立常住之体。
* 工程侧：所有权与 RAII —— 值有明确起点与终点，离开作用域即结束。
* 用意：让资源的生灭可见，减少「好像一直在」的隐式假设。
* 限度：GC、共享所有权在其他语境中同样有效；此处只是一种选择。

### 对照二：名色与类型

* 中观侧：名色相依，无单独自性。
* 工程侧：`Trait` / `Enum` / 穷尽 `match` —— 状态被命名，分支被显式处理。
* 用意：减少未命名状态与静默忽略。
* 限度：类型系统不能证明业务正确性；它只约束可表达的结构。

### 对照三：空性与零成本

* 中观侧：空不是无，而是无自性；缘起故有，有故空。
* 工程侧：零成本抽象 —— 高层形式在编译后可不留运行时实体。
* 用意：允许丰富语义而不必然支付固定代价。
* 限度：依赖具体编译器与目标架构；不是普遍物理定律。

---

## 3. 阶段

### 阶段一：语音与类型对照（已部分实现）

* 梵语语音分类（svara / vyañjana 等）映射为类型标记与分类函数
* 宏与穷尽匹配的练习

### 阶段二：过程与类型状态

* `TypedProcess` / `Cosmic` / `TypedResource`：用类型强制顺序
* 运行时版本保留，用于演示与日志

### 阶段三：克制扩展

* 仅在有明确可检验收益时增加 API
* 避免把叙事写成规范

---

## 4. 原则

1. **不立自性**：任何设计选择都可被质疑与替换。
2. **缘起可见**：依赖与生命周期尽量显式。
3. **不落两边**：既不神化 Rust，也不贬低其他工具。
4. **可检验优先于可宣称**。

Tat Tvam Asi.
